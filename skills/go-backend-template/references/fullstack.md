# Профиль с UI и IDL

Используй только при запросе профиля `fullstack`. Это запускаемый технический
каркас: Go backend в корне, отдельный React/TypeScript/Vite UI, protobuf-first
IDL. Оба последних каталога — уже подключённые и инициализированные Git-подмодули.
Не создавай удалённые репозитории, Git-историю и подмодули автоматически.

```sh
python3 <skill-dir>/scripts/scaffold.py <destination> --profile fullstack \
  --name <project-name> --module <module-path> --go-version <version> \
  --context <context> --model <model>
```

Существующие `.gitmodules` и содержимое подмодулей сохраняются. Генератор сначала
проверяет весь план: коллизии файлов и выходных каталогов генерации запрещены;
README в каждом репозитории дополняется отдельным блоком. Конфликт в любом из
трёх репозиториев должен остановить запись во всех. При ошибке не обходи проверку
и не выбирай другой каталог без указания пользователя.

## Контракты и границы

- `idl/proto/<project>/<context>/v1/*.proto`; package `<namespace>.<context>.v1`.
  Namespace — имя проекта без дефисов и подчёркиваний.
- Единый источник межконтекстного и сетевого API — `.proto`, включая
  `google.api.http` и OpenAPI tags. Не описывай внутренний сервис повторно через
  handwritten Go-интерфейсы или DTO.
- Buf генерирует protobuf/gRPC/gateway в `internal/gen/<context>/v1`, стабильный
  OpenAPI 2.0 — в `idl/openapi/<project>.yaml`. `swagger-typescript-api` создаёт
  Fetch-клиент в `ui/src/api/generated`, модуль по первому tag.
- Путь Go-пакетов задаётся managed mode для этого потребителя, а не зашивается
  в общие `.proto`. Зависимости googleapis/grpc-gateway сохраняют свои Go-пути.
- `ports/module` предоставляет `type API = <generated>.<Service>Server` и фабрику
  реализации. Bootstrap создаёт один экземпляр для прямых вызовов, HTTP и gRPC.
  Внутренний адаптер вызывает его методы напрямую с protobuf-сообщениями;
  сетевой потребитель использует сгенерированный gRPC-клиент.
- `domain`/`usecase` не импортируют `internal/gen`. Адаптер потребителя переводит
  protobuf и gRPC status в типы и ошибки сценария; реализация сервиса преобразует
  protobuf в вызовы usecase. Локальные интерфейсы зависимостей сценариев остаются
  рядом с потребителем и не дублируют публичный сервисный контракт.
- HTTP gateway подключается через `Register…HandlerServer` к тому же объекту
  напрямую, без loopback, gRPC-клиента и сериализации между модулями. Сетевой
  gRPC-сервер регистрирует этот же объект. Frontend — отдельная сборка/контейнер;
  в Compose публичен frontend с proxy `/api/`.
- Прямые вызовы и direct gateway обходят gRPC-interceptors. Общие проверки и
  бизнес-правила размещай в общей реализации/usecase; transport middleware
  применяется только к соответствующему входу. Профиль демонстрирует unary RPC;
  streaming требует отдельного адаптера и проверки возможностей gateway.
- Все результаты генерации коммитятся, обычная сборка их не генерирует.
  Buf breaking сравнивает с целевой веткой IDL (`master`, либо `IDL_BASE_REF`).
  Первая публикация без `.proto` в базе пропускает только breaking. Buf не
  заменяет ревью совместимости HTTP-маршрутов и поведения.
- Согласованное имя каталога с дефисом отличается от protobuf namespace;
  исключено только `PACKAGE_DIRECTORY_MATCH` из стандартных правил Buf.

## Завершение и проверка

Версии Buf, Node и генераторов закреплены в assets; смотри `idl/toolchain.json`.
При отсутствии инструментов установи их в доступную временную папку, не меняя
системные настройки. Профиль требует версию Go, поддерживаемую закреплёнными
зависимостями (сейчас Go 1.26.0+); не подменяй выбранную версию автоматически.

После записи файлов выполни `npm ci --prefix idl`, `npm ci --prefix ui`,
`make generate`, `go mod tidy`, затем `make check build` и
`docker compose config --quiet`. `buf.lock` и npm lockfiles включены в assets;
не обновляй зависимости без причины. Приведи созданные Go-файлы к gofmt.

Единственный работающий RPC — техническая проверка процесса с HTTP-маршрутом
`/api/v1/health`, общей реализацией в `internal/platform/health` и alias API в
`internal/platform/health/ports/module`. Тест без слушателей сравнивает прямой
вызов и HTTP handler через recorder; интеграционный тест сравнивает HTTP и
сетевой gRPC. Стартовый UI вызывает HTTP через генерируемый клиент.
Бизнес-контексты остаются заготовками. Не добавляй БД, CI, авторизацию и бизнес-код
без запроса. Контейнеры автоматически не запускай.
